## Ambiguities and chosen interpretations

- The screenshot allows a publicly available diabetes dataset and gives Pima as its example. This project uses that example's authentic public mirror. The full 768-record public source is included with source attribution and checksum provenance. The mirror's redistribution license is unspecified and that uncertainty is documented.
- The title mentions disease prediction, while the scenario specifies diabetes. `Outcome` models the source's observed diabetes classification.
- The screenshot does not prescribe a train/test ratio or a selection method. The project uses approximate 60/20/20 training, validation and test splits by canonical feature content. Equal feature records share a split. Validation chooses the best model, and a separate test set evaluates all three.
- Precision, recall and F1 are calculated for positive class 1. This is stated explicitly, and confusion counts are also saved.
- Feature scaling is used where it affects the algorithm. Logistic Regression uses a StandardScaler, while tree-based models use assembled imputed features. The complete comparison includes the required scaling stage through the Logistic Regression pipeline.
- New patient records are absent from the supplied material. The pipeline demonstrates inference with real unseen test records after removing labels and accepts a user-provided feature CSV for external records.
- Missing values in the source include zero placeholders in medical measurements. The policy treats zero glucose, blood pressure, skin thickness, insulin and BMI as missing and learns medians from training only. Zero pregnancies remains valid.
- Spark executes the full ML implementation. The default local master provides a runnable development environment. A cluster master and shared storage can be configured for distributed deployment.
